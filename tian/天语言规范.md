# 天语言正式规范 v0.1（Tian Language Specification）

> 本文档为天语言的唯一标准。v0.1 定稿后不再改动既有规则；新增功能以追加章节的方式进行。
> 编译器实现（tc）必须以本文档为准。

---

## 1. 基础信息

| 项目 | 值 |
|------|-----|
| 语言名（中） | 天 |
| 语言名（英） | Tian |
| 源码后缀 | `.t` |
| 编译器名称 | `tc`（Tian Compiler） |
| 第一阶段后端 | C 中转（`--emit-c` 生成 C 源码，gcc 编译） |
| 第二阶段后端 | LLVM 原生可执行文件（`tc build`） |
| 宿主实现语言 | Rust |

设计定位：取 C 之所长（极简、编译快、零运行时、可自由链接 C），取 Rust 之所长（强类型、安全），比 Rust 简单一个量级，比 C 安全一个量级。

## 2. 词法规则

### 2.1 标识符
- 首字符：Unicode 字母（含中文字符，如 `天`）或下划线 `_`。
- 后续字符：Unicode 字母、数字、下划线。
- 标识符大小写敏感。

### 2.2 保留标记字（w/ i/ f/ r/ e/）
以下五个标记为语言保留，后接 `/` 使用：

| 标记 | 含义 |
|------|------|
| `w/` | while 循环 |
| `i/` | if 分支 |
| `e/` | else 分支（必须紧跟 i/ 块） |
| `f/` | 函数定义 |
| `r/` | 函数返回（仅函数体内） |

判定规则：读入的标识符恰为 `w`、`i`、`f`、`r`、`e` 之一，且紧随其后为 `/`，**且当前不在表达式内部**（规范 2.7 上下文规则），则识别为流程标记；否则按普通标识符处理（`w`、`i`、`f`、`r`、`e` 单独作为变量名合法）。

> 已知取舍：表达式内对名为 `e`、`r` 等的变量做除法（如 `x=e/y`）会被误判为标记，须写 `x=(e)/y` 规避。与 2.7 的 `8//b` 取舍同类，为保持分词极简而有意保留。

### 2.3 注释
- `#` 开始，到行尾结束。单行注释，编译器直接跳过。
- 不支持块注释。

### 2.4 数字字面量
- 整数：`[0-9]+`，如 `20`、`100`。
- 浮点：`[0-9]+.[0-9]+`（小数点前后必须有数字），如 `3.14`。不支持 `1.` 或 `.5`。

### 2.5 字符串字面量
- 双引号包裹：`"你好"`。
- 支持转义：`\"` `\\` `\n` `\t`。
- 字符串不可跨行。

### 2.6 运算符与标点

| 符号 | 含义 |
|------|------|
| `+` `-` `*` `/` | 算术运算（`/` 的歧义判定见 2.7） |
| `<` `>` `<=` `>=` `==` `!=` | 比较运算，结果为 bool |
| `=` | 赋值 |
| `(` `)` | 函数参数 / 括号表达式 |
| `{` `}` | 语句块 |
| `,` | 参数分隔 |
| `:` | 类型标注 |
| `` ` `` | 打印语句前缀 |
| `/` | 只读声明前缀（紧贴标识符时）或除号（其余情况） |
| `//` | 可变声明前缀（紧贴标识符时） |

### 2.7 分词核心判定逻辑（斜杠歧义处理，全语言最关键规则）【v0.1.1 修订】

词法器读到 `/` 时，按以下顺序判定：

1. **上下文检查**：若前一个 Token 是标识符、数字、字符串、bool 或 `)`（即当前处于表达式内部）→ `/` 一律为**除号**。
2. **前缀检查**（仅当不在表达式内）：下一个字符是 `/`，且再下一个字符是字母或下划线 → `//` 为**可变声明前缀**（如 `//cnt`）；下一个字符是字母或下划线 → `/` 为**只读声明前缀**（如 `/a`）。
3. 其余一切情况 → **除号**。

> 修订说明：v0.1 纯前看规则会导致表达式内 `cnt/a` 被误判为声明，无法书写"变量/变量"除法。v0.1.1 引入上下文规则：表达式内（前一 Token 为操作数结尾）的 `/` 恒为除号，使 `a/2`、`cnt/a`、`f(x)/2` 均按 C 直觉工作。声明前缀只出现在语句边界或运算符/赋值之后。
>
> 已知取舍：`8//b` 形式（表达式内 + 双斜杠 + 标识符）中第一个 `/` 是除号、`/b` 会被判为声明而报语法错误；除法书写请使用 `8 / b` 或 `8/b`。

`w/` `i/` `f/` 标记字判定不受上下文影响：标识符恰为 w/i/f 且紧贴 `/` 即为流程标记（该三处位置本身不会是合法表达式语境）。

### 2.8 换行
- 换行符是**语句结束符**（类似 C 的 `;` 但更简单），词法器输出为独立的换行 Token。
- 连续多个换行等价于一个。
- `{` 之后、`}` 之前的换行同样为语句分隔。

## 3. 变量

| 语法 | 含义 |
|------|------|
| `/a=20` | 声明只读变量 a，初始化为 20，**不可再赋值** |
| `//b=1` | 声明可变变量 b，初始化为 1，**可再赋值** |
| `cnt=cnt+1` | 对已声明的可变变量赋值（不需要前缀） |
| `/num:i32=10` | 声明变量并手动标注类型 |

规则：
- 声明时**必须**初始化（`/a` 无初始化为语法错误）。
- 对只读变量二次赋值是**编译期错误**。
- 对未声明变量赋值是**编译期错误**。
- 类型自动推导；`/` 与 `//` 后可跟 `:类型` 手动标注。
- **前缀 `/` 必须紧贴标识符**：`/ a` 中间有空格时不是声明，会按除号处理并报语法错误（这是设计而非缺陷：紧贴性消除了歧义）。

## 4. 打印

语法：`` `表达式 ``

反引号开头 + 表达式，输出表达式求值结果到标准输出并换行。**bool 打印为 `true` / `false`**（v1.1 统一两后端行为）。

```
`a          打印变量 a
`a/2        打印表达式结果（表达式内 / 恒为除号，规范 2.7）
`"你好"     打印字符串
`cnt/a      打印除法结果
```

## 5. 流程控制

### 5.1 while 循环
```
w/条件{
    语句
}
```
条件为 bool 表达式。块内语句每行一条。

### 5.2 if / else 分支
```
i/条件{
    语句
}e/{
    语句
}
```
条件为 bool 表达式。`e/` 块可选，必须紧跟 `i/` 块之后。

### 5.3 函数
```
f/函数名(参数1:类型, 参数2:类型):返回类型 {
    语句
    r/表达式
}
```
- **类型标注可省略**：参数省略默认 i64，返回类型省略默认 i64（v0.2 兼容）。
- 参数为只读绑定，函数内不可对参数赋值。五种类型（i32/i64/f64/str/bool）均可用于参数与返回值。
- `r/表达式` 的类型须与返回类型一致：整数可隐式提升为 f64；i32 与 i64 之间按整数字面量范围规则放行；其余必须精确匹配。
- `r/` 裸返回该返回类型的零值：`0`（i32/i64）、`0.0`（f64）、`""` 的独立堆副本（str，可安全释放与打印，天权 11.1）、`false`（bool）。函数体落出末尾的隐式返回同此规则。
- 函数调用表达式的类型 = 声明的返回类型，可参与算术、比较、赋值。
- 实参类型须与形参一致，提升规则同返回值。
- 函数体只能访问自身参数，不能访问顶层变量（v0.1 约束延续）。
- 函数定义顺序无关，调用前必须有声明存在（编译期检查）。
- `r/` 出现在函数体外为编译期错误。

## 6. 类型系统

| 类型 | 说明 |
|------|------|
| `i32` | 32 位有符号整数 |
| `i64` | 64 位有符号整数 |
| `f64` | 双精度浮点 |
| `str` | UTF-8 字符串 |
| `bool` | 布尔值，字面量 `true` / `false` |

规则：
- 整数字面量默认推导为 `i64`，浮点字面量推导为 `f64`。
- **str 与数字类型混用是编译期错误**（如 `"a"+1`、`1+"a"`，需用 `tos()` 显式转换）。
- **str + str 合法**：字符串拼接（v0.3 起），结果为 str；str 仅支持 `+`，不支持 `-` `*` `/`。
- bool 只参与条件与比较，与数字不互通。
- i32 与 i64 混算默认提升为 i64；整数与 f64 混算提升为 f64。

## 7. 类型转换函数

| 函数 | 行为 |
|------|------|
| `toi(表达式)` | 数字 → 整数（f64 截断小数；str → 解析失败为编译期错误，仅接受字符串字面量） |
| `tos(表达式)` | 数字/bool → 字符串 |

## 8. 编译命令规范

| 命令 | 行为 |
|------|------|
| `tc xxx.t --emit-c` | 编译为中间 C 代码，输出 `xxx.c` |
| `tc run xxx.t` | 生成 C → 调用 cc/gcc 编译 → 运行，一步到位 |
| `tc build xxx.t` | 生成原生可执行文件 `xxx`（v0.2 经 C 后端 + 系统编译器链接；LLVM 后端为后续阶段） |

开发阶段辅助命令：
| 命令 | 行为 |
|------|------|
| `tc lex xxx.t` | 仅执行词法分析，打印 Token 流（调试用） |

## 9. 标准测试样例 main.t（定稿）

```
# main.t 天道示例
/a=20
`a/2
//cnt=1
w/cnt<=3{
    cnt=cnt+1
    `cnt/a
}
f/add(x,y){
    /res=x+y
    `res
}
add(10,90)
```

预期输出：
```
10
0
0
0
100
```
> `a/2` = 20/2 = 10；循环中 `cnt/a` = 2/20、3/20、4/20（整数除法向零截断，均为 0）；`add(10,90)` 打印 100。

## 11. 天权——内存安全模型（v2.0）

天权是天语言的内存安全机制：**所有权 + 移动语义 + 确定性释放**，无 GC、无引用计数。v2.0 作用于 str（唯一的堆类型）；数值与 bool 为纯值类型，不受天权约束。

### 11.1 所有权
1. 每个 str 变量**拥有**其内存。绑定字面量或 `tos()` 结果时，编译器自动复制（`__t_dup`），保证变量持有的指针总是可释放的堆内存。
2. 拼接（`+`）与返回 str 的函数调用产生新的堆内存，归接收变量所有。

### 11.2 移动
1. **赋值、传参、返回 = 移动所有权**；源变量随即失效（编译器在运行时将其置空）。
2. **使用已失效的变量是编译期错误**（use-after-move 检查）。
3. 失效变量可通过对 `//` 可变变量重新赋值复活。
4. **读取操作只借用**：打印、比较（`==`/`!=`）、拼接的操作数、`copy()` 的参数都不移动。
5. `copy(s)` 显式复制字符串，产生新的独立所有者。

### 11.3 确定性释放
1. 变量离开作用域时自动释放（编译器插入释放调用）。
2. 重新绑定前自动释放旧值（循环内重复声明同样安全，无泄漏、无重复释放）。
3. 移动置空保证所有释放调用天然安全。

### 11.4 v2.0 已知边界（均为内存安全，仅影响内存占用）
1. 表达式中间值（如 `` `a+b+c `` 的中间串）在语句结束后释放，嵌套中间串延迟到进程退出。
2. 含 `r/` 早退的路径上，其后的局部释放被跳过（进程退出回收）。
3. 作用域规则（v2.0 起严格词法作用域）：块内声明的变量块外不可见；跨块的移动取保守判定（任一分支中移动即视为已移动）。

### 11.5 v2.1 已实现：借用（只读）
1. `&s` 产生对 str 变量 s 的**只读借用**，不移动 s、不复制、不释放——借用只是一个临时的只读视图。
2. 借用形参标注为 `&str`。被调函数对借用形参**不是所有者**：不得释放、不得移动、不得将其绑定给 str 变量、不得返回。
3. 借用的合法位置仅为 `&str` 形参的实参（`g(&s)`）；在其他表达式位置出现 `&` 是编译期错误。借用值在只读位（打印、比较、拼接、`tos()`、`copy()`）视同 str 使用。
4. **借用不逃逸**：`&str` 形参不可作为返回值（返回类型也不允许标注 `&str`）；需要把借用变为所有权，用 `copy(x)` 产生独立副本。
5. 借用是移动语义的安全补充：函数只想读不想接管时用 `&str`，想接管时用 `str`（规范 11.2）。这消除了"只为读一个字符串就被迫放弃所有权"的别扭写法。

### 11.6 后续规划
非 str 堆类型（struct/数组）接入天权；区域（Region）粗粒度生命周期分析；写借用（`&mut`，排除别名）暂不引入——v2.x 以只读借用的能力上限为界，保持检查器简单可证明。

## 12. 语义锚点（v2.2）

语义锚点把"函数的约定"写进代码本体，由编译器编译为可执行的校验，而非停留在注释里。锚点写在函数体的最前面（大括号后、第一条语句前），每行一条，以 `@` 开头。

### 12.1 三种锚点
1. `@pre: <bool表达式>` —— 前置条件。编译为函数入口的运行时守卫：表达式为 false 时立即打印失败信息并 `exit(1)`。
2. `@post: <bool表达式>` —— 后置条件。表达式中可使用伪变量 `ret` 指代返回值；编译为 helper 函数（`__t_post_<函数名>`），在每个返回点校验，失败即 `exit(1)`。
3. `@example: <调用> -> <期望值>` —— 自检样例。必须调用本函数自身；编译为程序启动时的自测（main 执行顶层语句之前运行），实际结果与期望值不等则 `exit(1)`。str 结果用值语义比较（`__t_seq`），数值/bool 用 `==`。

### 12.2 规则
1. `@pre` / `@post` 表达式必须是 bool 类型，否则编译期报错；`@post` 的 `ret` 伪变量类型即函数返回类型，作用域内不可与用户变量 `ret` 冲突（内部以 `#ret` 存储规避）。
2. `@example` 的调用返回类型与期望值类型都必须与函数返回类型一致；调用其他函数是编译期错误。
3. 锚点校验发生在运行时（非证明系统）：契约成立依赖调用方自觉，违约即快速失败——这是"假设崩溃好过静默出错"的设计取舍。
4. 锚点表达式遵循普通表达式规则（借用实参可用字符串字面量等静态存储值，规范 11.5）。
5. 未知锚点名（`@foo`）在解析期报错；可用锚点仅 `@pre`、`@post`、`@example`。

### 12.3 tc test 命令
`tc test xxx.t` 只运行 `@example` 自检（不执行顶层语句）：全部通过静默退出 0，任一失败非零退出。供 CI / AI 代理在改动后快速验证函数级行为不变。

## 13. 结构化差分诊断（v2.3）

`tc xxx.t --diagnose-json` 以 JSON 输出编译诊断：`{"stage","error","line","message","hint","candidates"}`。`stage` 为 `lex`/`parse`/`check`/`ok`；词法/解析/检查失败时 `line` 定位出错行，`hint` 给出修复方向，`candidates` 给出相似标识符候选（编辑距离 ≤ 2 或前缀/后缀/包含匹配）。供 AI 与工具链程序化读取，替代"人读报错文本再猜"的循环。

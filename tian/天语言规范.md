# 天语言正式规范 v0.1（Tian Language Specification）

> 本文档为天语言的唯一标准。v0.1 定稿后不再改动既有规则；新增功能以追加章节的方式进行。
> 编译器实现（tc）必须以本文档为准。

---

## 1. 基础信息

| 项目 | 值 |
|------|-----|
| 语言名（中） | 天 |
| 语言名（英） | Tian |
| 源码后缀 | `.t` |
| 编译器名称 | `tc`（Tian Compiler） |
| 第一阶段后端 | C 中转（`--emit-c` 生成 C 源码，gcc 编译） |
| 第二阶段后端 | LLVM 原生可执行文件（`tc build`） |
| 宿主实现语言 | Rust |

设计定位：取 C 之所长（极简、编译快、零运行时、可自由链接 C），取 Rust 之所长（强类型、安全），比 Rust 简单一个量级，比 C 安全一个量级。

## 2. 词法规则

### 2.1 标识符
- 首字符：Unicode 字母（含中文字符，如 `天`）或下划线 `_`。
- 后续字符：Unicode 字母、数字、下划线。
- 标识符大小写敏感。

### 2.2 保留标记字（w/ i/ f/ r/ e/）
以下五个标记为语言保留，后接 `/` 使用：

| 标记 | 含义 |
|------|------|
| `w/` | while 循环 |
| `i/` | if 分支 |
| `e/` | else 分支（必须紧跟 i/ 块） |
| `f/` | 函数定义 |
| `r/` | 函数返回（仅函数体内） |

判定规则：读入的标识符恰为 `w`、`i`、`f`、`r`、`e` 之一，且紧随其后为 `/`，**且当前不在表达式内部**（规范 2.7 上下文规则），则识别为流程标记；否则按普通标识符处理（`w`、`i`、`f`、`r`、`e` 单独作为变量名合法）。

> 已知取舍：表达式内对名为 `e`、`r` 等的变量做除法（如 `x=e/y`）会被误判为标记，须写 `x=(e)/y` 规避。与 2.7 的 `8//b` 取舍同类，为保持分词极简而有意保留。

### 2.3 注释
- `#` 开始，到行尾结束。单行注释，编译器直接跳过。
- 不支持块注释。

### 2.4 数字字面量
- 整数：`[0-9]+`，如 `20`、`100`。
- 浮点：`[0-9]+.[0-9]+`（小数点前后必须有数字），如 `3.14`。不支持 `1.` 或 `.5`。

### 2.5 字符串字面量
- 双引号包裹：`"你好"`。
- 支持转义：`\"` `\\` `\n` `\t`。
- 字符串不可跨行。

### 2.6 运算符与标点

| 符号 | 含义 |
|------|------|
| `+` `-` `*` `/` | 算术运算（`/` 的歧义判定见 2.7） |
| `<` `>` `<=` `>=` `==` `!=` | 比较运算，结果为 bool |
| `=` | 赋值 |
| `(` `)` | 函数参数 / 括号表达式 |
| `{` `}` | 语句块 |
| `,` | 参数分隔 |
| `:` | 类型标注 |
| `` ` `` | 打印语句前缀 |
| `/` | 只读声明前缀（紧贴标识符时）或除号（其余情况） |
| `//` | 可变声明前缀（紧贴标识符时） |

### 2.7 分词核心判定逻辑（斜杠歧义处理，全语言最关键规则）【v0.1.1 修订】

词法器读到 `/` 时，按以下顺序判定：

1. **上下文检查**：若前一个 Token 是标识符、数字、字符串、bool 或 `)`（即当前处于表达式内部）→ `/` 一律为**除号**。
2. **前缀检查**（仅当不在表达式内）：下一个字符是 `/`，且再下一个字符是字母或下划线 → `//` 为**可变声明前缀**（如 `//cnt`）；下一个字符是字母或下划线 → `/` 为**只读声明前缀**（如 `/a`）。
3. 其余一切情况 → **除号**。

> 修订说明：v0.1 纯前看规则会导致表达式内 `cnt/a` 被误判为声明，无法书写"变量/变量"除法。v0.1.1 引入上下文规则：表达式内（前一 Token 为操作数结尾）的 `/` 恒为除号，使 `a/2`、`cnt/a`、`f(x)/2` 均按 C 直觉工作。声明前缀只出现在语句边界或运算符/赋值之后。
>
> 已知取舍：`8//b` 形式（表达式内 + 双斜杠 + 标识符）中第一个 `/` 是除号、`/b` 会被判为声明而报语法错误；除法书写请使用 `8 / b` 或 `8/b`。

`w/` `i/` `f/` 标记字判定不受上下文影响：标识符恰为 w/i/f 且紧贴 `/` 即为流程标记（该三处位置本身不会是合法表达式语境）。

### 2.8 换行
- 换行符是**语句结束符**（类似 C 的 `;` 但更简单），词法器输出为独立的换行 Token。
- 连续多个换行等价于一个。
- `{` 之后、`}` 之前的换行同样为语句分隔。

## 3. 变量

| 语法 | 含义 |
|------|------|
| `/a=20` | 声明只读变量 a，初始化为 20，**不可再赋值** |
| `//b=1` | 声明可变变量 b，初始化为 1，**可再赋值** |
| `cnt=cnt+1` | 对已声明的可变变量赋值（不需要前缀） |
| `/num:i32=10` | 声明变量并手动标注类型 |

规则：
- 声明时**必须**初始化（`/a` 无初始化为语法错误）。
- 对只读变量二次赋值是**编译期错误**。
- 对未声明变量赋值是**编译期错误**。
- 类型自动推导；`/` 与 `//` 后可跟 `:类型` 手动标注。
- **前缀 `/` 必须紧贴标识符**：`/ a` 中间有空格时不是声明，会按除号处理并报语法错误（这是设计而非缺陷：紧贴性消除了歧义）。

## 4. 打印

语法：`` `表达式 ``

反引号开头 + 表达式，输出表达式求值结果到标准输出并换行。**bool 打印为 `true` / `false`**（v1.1 统一两后端行为）。

```
`a          打印变量 a
`a/2        打印表达式结果（表达式内 / 恒为除号，规范 2.7）
`"你好"     打印字符串
`cnt/a      打印除法结果
```

## 5. 流程控制

### 5.1 while 循环
```
w/条件{
    语句
}
```
条件为 bool 表达式。块内语句每行一条。

### 5.2 if / else 分支
```
i/条件{
    语句
}e/{
    语句
}
```
条件为 bool 表达式。`e/` 块可选，必须紧跟 `i/` 块之后。

### 5.3 函数
```
f/函数名(参数1:类型, 参数2:类型):返回类型 {
    语句
    r/表达式
}
```
- **类型标注可省略**：参数省略默认 i64，返回类型省略默认 i64（v0.2 兼容）。
- 参数为只读绑定，函数内不可对参数赋值。五种类型（i32/i64/f64/str/bool）均可用于参数与返回值。
- `r/表达式` 的类型须与返回类型一致：整数可隐式提升为 f64；i32 与 i64 之间按整数字面量范围规则放行；其余必须精确匹配。
- `r/` 裸返回该返回类型的零值：`0`（i32/i64）、`0.0`（f64）、`""` 的独立堆副本（str，可安全释放与打印，天权 11.1）、`false`（bool）。函数体落出末尾的隐式返回同此规则。
- 函数调用表达式的类型 = 声明的返回类型，可参与算术、比较、赋值。
- 实参类型须与形参一致，提升规则同返回值。
- 函数体只能访问自身参数，不能访问顶层变量（v0.1 约束延续）。
- 函数定义顺序无关，调用前必须有声明存在（编译期检查）。
- `r/` 出现在函数体外为编译期错误。

## 6. 类型系统

| 类型 | 说明 |
|------|------|
| `i32` | 32 位有符号整数 |
| `i64` | 64 位有符号整数 |
| `f64` | 双精度浮点 |
| `str` | UTF-8 字符串 |
| `bool` | 布尔值，字面量 `true` / `false` |

规则：
- 整数字面量默认推导为 `i64`，浮点字面量推导为 `f64`。
- **str 与数字类型混用是编译期错误**（如 `"a"+1`、`1+"a"`，需用 `tos()` 显式转换）。
- **str + str 合法**：字符串拼接（v0.3 起），结果为 str；str 仅支持 `+`，不支持 `-` `*` `/`。
- bool 只参与条件与比较，与数字不互通。
- i32 与 i64 混算默认提升为 i64；整数与 f64 混算提升为 f64。

## 7. 类型转换函数

| 函数 | 行为 |
|------|------|
| `toi(表达式)` | 数字 → 整数（f64 截断小数；str → 解析失败为编译期错误，仅接受字符串字面量） |
| `tos(表达式)` | 数字/bool → 字符串 |
| `tof(表达式)`（v4.4） | str → f64：运行时 strtod 全量消费，非全量/非法内容打印 `运行时错误：无效数字` 并 exit(1)；数字类型 → 截断/转换为 f64 |

## 11. 天权——内存安全模型（v2.0）

天权是天语言的内存安全机制：**所有权 + 移动语义 + 确定性释放**，无 GC、无引用计数。v2.0 作用于 str（唯一的堆类型）；数值与 bool 为纯值类型，不受天权约束。

### 11.1 所有权
1. 每个 str 变量**拥有**其内存。绑定字面量或 `tos()` 结果时，编译器自动复制（`__t_dup`），保证变量持有的指针总是可释放的堆内存。
2. 拼接（`+`）与返回 str 的函数调用产生新的堆内存，归接收变量所有。

### 11.2 移动
1. **赋值、传参、返回 = 移动所有权**；源变量随即失效（编译器在运行时将其置空）。
2. **使用已失效的变量是编译期错误**（use-after-move 检查）。
3. 失效变量可通过对 `//` 可变变量重新赋值复活。
4. **读取操作只借用**：打印、比较（`==`/`!=`）、拼接的操作数、`copy()` 的参数都不移动。
5. `copy(s)` 显式复制字符串，产生新的独立所有者。

### 11.3 确定性释放
1. 变量离开作用域时自动释放（编译器插入释放调用）。
2. 重新绑定前自动释放旧值（循环内重复声明同样安全，无泄漏、无重复释放）。
3. 移动置空保证所有释放调用天然安全。

### 11.4 v2.0 已知边界（均为内存安全，仅影响内存占用）
1. 表达式中间值（如 `` `a+b+c `` 的中间串）在语句结束后释放，嵌套中间串延迟到进程退出。
2. 含 `r/` 早退的路径上，其后的局部释放被跳过（进程退出回收）。
3. 作用域规则（v2.0 起严格词法作用域）：块内声明的变量块外不可见；跨块的移动取保守判定（任一分支中移动即视为已移动）。

### 11.5 v2.1 已实现：借用（只读）
1. `&s` 产生对 str 变量 s 的**只读借用**，不移动 s、不复制、不释放——借用只是一个临时的只读视图。
2. 借用形参标注为 `&str`。被调函数对借用形参**不是所有者**：不得释放、不得移动、不得将其绑定给 str 变量、不得返回。
3. 借用的合法位置仅为 `&str` 形参的实参（`g(&s)`）；在其他表达式位置出现 `&` 是编译期错误。借用值在只读位（打印、比较、拼接、`tos()`、`copy()`）视同 str 使用。
4. **借用不逃逸**：`&str` 形参不可作为返回值（返回类型也不允许标注 `&str`）；需要把借用变为所有权，用 `copy(x)` 产生独立副本。
5. 借用是移动语义的安全补充：函数只想读不想接管时用 `&str`，想接管时用 `str`（规范 11.2）。这消除了"只为读一个字符串就被迫放弃所有权"的别扭写法。

### 11.6 后续规划
非 str 堆类型（struct/数组）接入天权；区域（Region）粗粒度生命周期分析；写借用（`&mut`，排除别名）暂不引入——v2.x 以只读借用的能力上限为界，保持检查器简单可证明。

## 12. 语义锚点（v2.2）

语义锚点把"函数的约定"写进代码本体，由编译器编译为可执行的校验，而非停留在注释里。锚点写在函数体的最前面（大括号后、第一条语句前），每行一条，以 `@` 开头。

### 12.1 三种锚点
1. `@pre: <bool表达式>` —— 前置条件。编译为函数入口的运行时守卫：表达式为 false 时立即打印失败信息并 `exit(1)`。
2. `@post: <bool表达式>` —— 后置条件。表达式中可使用伪变量 `ret` 指代返回值；编译为 helper 函数（`__t_post_<函数名>`），在每个返回点校验，失败即 `exit(1)`。
3. `@example: <调用> -> <期望值>` —— 自检样例。必须调用本函数自身；编译为程序启动时的自测（main 执行顶层语句之前运行），实际结果与期望值不等则 `exit(1)`。str 结果用值语义比较（`__t_seq`），数值/bool 用 `==`。

### 12.2 规则
1. `@pre` / `@post` 表达式必须是 bool 类型，否则编译期报错；`@post` 的 `ret` 伪变量类型即函数返回类型，作用域内不可与用户变量 `ret` 冲突（内部以 `#ret` 存储规避）。
2. `@example` 的调用返回类型与期望值类型都必须与函数返回类型一致；调用其他函数是编译期错误。
3. 锚点校验发生在运行时（非证明系统）：契约成立依赖调用方自觉，违约即快速失败——这是"假设崩溃好过静默出错"的设计取舍。
4. 锚点表达式遵循普通表达式规则（借用实参可用字符串字面量等静态存储值，规范 11.5）。
5. 未知锚点名（`@foo`）在解析期报错；可用锚点仅 `@pre`、`@post`、`@example`。

### 12.3 tc test 命令
`tc test xxx.t` 只运行 `@example` 自检（不执行顶层语句）：全部通过静默退出 0，任一失败非零退出。供 CI / AI 代理在改动后快速验证函数级行为不变。

## 13. 结构化差分诊断（v2.3）

`tc xxx.t --diagnose-json` 以 JSON 输出编译诊断：`{"stage","error","line","message","hint","candidates"}`。`stage` 为 `lex`/`parse`/`check`/`ok`；词法/解析/检查失败时 `line` 定位出错行，`hint` 给出修复方向，`candidates` 给出相似标识符候选（编辑距离 ≤ 2 或前缀/后缀/包含匹配）。供 AI 与工具链程序化读取，替代"人读报错文本再猜"的循环。

## 14. 结构体（v3.0）

结构体是天语言的第二个堆类型：**值语义的复合记录**，整体受天权所有权约束（规范 14.4）。v3.0 字段仅支持五种基本类型（i32/i64/f64/str/bool），不支持结构体字段内嵌（嵌套会使深释放与拷贝语义复杂化，留待后续）。

### 14.1 声明
```
struct Point{x:i64  y:str}
```
- `struct` 为保留字。声明必须包含至少一个字段；字段重复定义是编译期错误。
- 字段之间用 `,` 或换行分隔；结构体必须先声明后使用；重复声明是编译期错误。
- 字段类型不能是 `&str`（借用不可存储）也不能是其他结构体。

### 14.2 构造
```
//p=Point{1,2}          # 位置式：按声明顺序
//q=Point{y:10  x:20}   # 命名式：顺序无关
```
- 字面量为堆分配的新所有者，归接收变量所有。
- 位置式与命名式不可混用；字段数须与声明完全一致；类型须匹配（提升规则同规范 5.3）。

### 14.3 字段访问与赋值
```
`p.x        # 读取（借用，不移动）
p.x=100     # 赋值：要求 p 为 // 可变变量且未被移动
```
- 只读变量（`/`）的字段不可赋值；已移动变量的字段不可访问。
- str 字段赋值时旧值自动释放（规范 11.3.2 同规则）。

### 14.4 天权对结构体的约束
1. **整体移动**：赋值、传参、返回结构体 = 移动整个结构体；源变量随即失效，使用是编译期错误。
2. **字段不可移出**：把字段移出为独立所有者（绑定 `//a=p.x`、返回 `p.x`）是编译期错误——字段与结构体会双释放。需要副本用 `copy(p.x)`。
3. **确定性释放**：结构体离开作用域时释放全部 str 字段；str 字段重赋值前释放旧值。
4. **借用字段（v3.1）**：`&p.name` 借用结构体的 str 字段（只读视图，不移动、不复制、不释放）。基表达式必须是结构体变量（已移动则报错），字段必须是 str 类型；借用不逃逸（不可绑定、不可返回）。基变量为非结构体或字段非 str 是编译期错误。

### 14.5 限制
- 结构体整体不可打印（打印具体字段如 `p.x`）、不可参与 `==`/`!=`（请比较字段）、不可用于 `@example` 期望值比对。
- 结构体的字段可被 `&` 借用（`&p.name`，规范 14.4.4）；`copy()` 是从字段获取独立所有权的唯一路径。

## 15. 运行时快速失败（v3.2）

天语言的运行时错误遵循单一哲学（与 12.2.3 一致）：**崩溃好过静默出错**。所有运行时错误统一走 `__t_panic`：向 stderr 打印一行 `运行时错误：<原因>`，进程以退出码 1 终止。两个后端（C 中转与 Cranelift 原生）行为完全一致。

### 15.1 整数除零
- 整数除法（i32/i64）的除数为零时，编译器插入守卫（C 后端经 `__t_idiv_i/__t_idiv_l`，原生后端插入比较与 `__t_panic` 调用），运行时打印 `运行时错误：除数为零` 并 exit(1)。
- v3.2 之前的行为（已废弃）：C 后端为未定义行为（可能静默输出垃圾值），原生后端为 SIGFPE 陷阱（退出码 132）——双后端不一致且不符合快速失败哲学。

### 15.2 浮点除零
- f64 除零遵循 IEEE 754：得 inf/-inf/nan，**不**触发 panic。浮点是非精确运算，infinite/nan 是合法值。

### 15.3 后续扩展
数组越界、str 索引越界等未来运行时检查全部走同一 `__t_panic` 出口；错误信息保持单行、可被 AI/工具链 grep。

## 16. 固定长度数组（v3.3）

数组是**纯值类型**（不参与天权所有权，与数值/bool 同类），元素仅支持 i32/i64/f64/bool 四种基本类型。str 元素数组、数组字段、数组参数/返回值均为 v3.3 明确不支持（见 16.5）。

### 16.1 声明与值语义
```
//a=i64[3]{10,20,30}     # 类型标注可省略，由字面量推导
/f2=f64[2]{1.5,2.5}
```
- 类型写法 `元素类型[长度]`，长度必须为正整数字面量。
- 整体赋值（`//b=a`、`a=b`）为**拷贝语义**：逐元素复制，两数组此后独立。
- 循环内重复声明安全：每轮重新初始化（值类型，无释放问题）。

### 16.2 元素校验
- 字面量元素个数必须与长度一致（编译期错误）。
- 元素类型必须与声明一致（提升规则同规范 5.3：i32 字面量可入 i64 数组等）。

### 16.3 索引与 len
```
`a[0]        # 读
a[i+1]=5     # 写（要求 a 为 // 可变）
`len(a)      # 长度，编译期常量 i64
```
- 下标为整数表达式（i32/i64）。
- **编译期越界检查**：下标为字面量（含负号字面量）时越界即编译期错误。
- **运行时越界检查**：动态下标经守卫，越界打印 `运行时错误：数组越界` 并 exit(1)（规范 15.1 同一出口）。

### 16.4 限制
- 数组整体不可打印、不可参与 `==`/`!=` 比较、不可拼接。
- 只读数组（`/` 声明）不可修改元素。

### 16.5 v3.3 明确不做
1. str 元素数组（str 参与天权，数组值语义与所有权模型冲突，待专项设计）。
2. 数组作为返回值（C 返回栈数组为悬垂指针）。
3. 数组作为结构体字段、嵌套数组、动态长度。

### 16.6 数组参数（v3.4）
- 数组可作为函数参数，类型写 `x:i64[3]`。传递为**只读视图**（零拷贝指针）：被调函数读到的就是调用方的数组，但参数是只读绑定，不可写元素、不可整体赋值——观察上与传值等价。
- 实参必须是数组变量（字面量无存储，编译期错误）；形参与实参的元素类型和长度必须一致。
- 可多次传同一数组，源变量不失效（纯值类型，无移动）。
- 长度不一致是编译期错误：`i64[2]` 与 `i64[3]` 是不同类型。

### 16.7 len() 内建（v3.3/v3.5）
- `len(数组)` → 数组长度（编译期常量 i64）。
- `len(str)` → 字符串的 **UTF-8 字节数**（与 C strlen 一致）：`len("天道")` 为 6。字符（码点）计数留待将来 `chars()`，v0.x 不引入。
- 其他类型（数字/bool/结构体）用于 len() 是编译期错误。

## 17. 模块系统（v3.6）

`use 名字` 把同目录下的 `名字.t` 接入当前文件一起编译（规范第 17 节）：

```
use math
`add(3,4)
```

1. 解析规则：`use` 后跟标识符，加载该目录下 `名字.t`；其 token 流接入**同一个解析器实例**——结构体表与数组类型表跨文件共享，类型索引无需重排。
2. 递归导入：被导入文件内可继续 `use`；**循环导入与重复导入按已访问集合跳过**（同一文件只并入一次）。
3. 跨文件符号：结构体、函数、顶层变量在合并后的程序中共享命名空间；重复定义是编译期错误（函数重名由类型检查器拦截，结构体重名由解析器拦截）。
4. 报错定位：非入口文件内的语法错误带 `[文件名]` 前缀。
5. `use` 只能出现在顶层（可与其他顶层语句混排，但建议置于文件首部）。
6. `use` 是保留字，不可作变量名。

## 18. 条件表达式 sel（v3.7）

`sel(条件, 值1, 值2)` 是表达式版的三分支选择（`i/` 是语句，不能出现在表达式里）：

```
`sel(a<b, a, b)          # max
//m=sel(x>0, x, 0-x)     # abs
```

1. **惰性求值**：只求值被选中的分支（两后端一致：C 三元表达式 / Cranelift 块参数）。未选中分支的运行时错误（如除零）不会触发。
2. 条件必须是 bool。
3. 分支类型仅支持数值与 bool：同型直接用；i32/i64 混用统一为 i64；整数/f64 混用统一为 f64。str、结构体、数组分支是编译期错误（str 分支的落选值会泄漏堆内存，结构体/数组涉及深拷贝协议）。
4. 分支可以是任意表达式（函数调用、sel 嵌套等），但落选分支若有副作用（移动所有权、panic）将不被执行——**不要在 sel 分支里写有副作用的代码**，副作用语句请用 `i/`。

## 19. 循环控制 break / continue（v3.8）

```
w/条件{
    i/…{
        break          # 跳出本层循环
    }
    i/…{
        continue       # 跳过本轮剩余语句，回到条件判断
    }
}
```

1. `break` 跳出**最近一层** `w/` 循环；`continue` 跳回最近一层循环的条件判断。
2. 只能出现在 `w/` 循环体内，否则是编译期错误（`break`/`continue` 为保留字）。
3. 已知边界（与规范 11.4.2 的 `r/` 早退同类）：跳转跳过其后语句的 str/结构体释放，这些值延迟到进程退出回收——只影响内存占用，不影响内存安全。
4. 嵌套循环中 break/continue 只作用于最近一层。

## 20. 源码格式化 tc fmt（v3.9）

`tc fmt xxx.t` 输出规范化源码到 stdout（不写回原文件）：

1. **规范化内容**：4 空格缩进；二元运算符两侧空格；子表达式按优先级加最小括号；顶层顺序规范化为 `use` → `struct` → 函数 → 顶层语句；被 `use` 导入文件中的结构体与函数不重复输出（由其模块文件自含，`imported` 标记）。
2. **验收标准——幂等**：`fmt(fmt(x)) == fmt(x)`；且格式化输出再次编译后运行结果与原程序完全一致（黄金测试对每个用例自动做此双检）。
3. fmt 之前会执行完整类型检查，有编译错误的文件不出格式化输出。
4. 注释与空行不保留（AST 之外的信息）；给 AI 的建议：格式化仅用于 diff 规范化，不要把 fmt 输出覆盖回带注释的源文件。

## 21. 断言内建 panic / check（v4.0）

```
panic("不可达状态")           # 立即失败
check(条件, "失败原因")       # 条件为 false 时失败
```

1. `panic(msg)`：向 stderr 打印 `运行时错误：msg` 并 exit(1)——与除零/越界同一快速失败出口（规范第 15 节）。
2. `check(cond, msg)`：cond 必须为 bool，msg 必须为 str；cond 为 false 等价于 `panic(msg)`。用于函数内防御性断言（与 `@pre` 互补：@pre 约束调用方，check 防御内部状态）。
3. 两者均为**语句**（无值）；panic 之后的语句不可达。
4. `check` 的 cond 求值先于 msg（与书写顺序一致）。

## 22. 动态数组（v4.0）

`[]T` 是可增长的序列，元素 T 仅支持 i32/i64/f64/bool（8 字节槽，与定长数组一致）。**它是天权堆类型**：与 str/结构体同一套所有权规则（规范 11.2/14.4）。

### 22.1 创建与 push / pop（v4.0/v4.1）
```
//a=[]i64{1,2}       # 字面量：任意个数元素
push(a, 30)          # 语句级追加；容量不足时自动倍增
pop(a)               # 语句级移除末元素；空数组时 panic
`len(a)              # 运行时长度
`a[0]  `a[1]         # 索引读（越界：运行时 panic，规范 15.1 出口）
a[1]=99              # 索引写（要求 a 为 // 可变）
```
- `push`/`pop` 只能作为语句；push 可能引发内存重分配，**变量在 push 后指向新内存**（编译器自动重新绑定，调用方无感）。
- 字面量初始化按 push 语义逐元素追加。

### 22.2 形参上的原地修改（v4.1）
动态数组形参是**所有者**（调用方的变量已移走，无别名风险），因此允许在形参上直接 `push`/`pop`/元素赋值——这是"修改型函数接管数组、修改后返回交还"惯用法的基础：
```
f/heap_push(h:[]i64, v:i64):[]i64{
    push(h, v)
    //n=len(h)
    r/sift_up(h, n-1)   # 注意：h 移入 sift_up 后不可再用，len 需提前求值
}
```
标量/str/结构体形参保持只读（规范 5.3），不适用本条。

### 22.3 所有权
1. 赋值、传参、返回 = **移动**整个数组（指针移交，源失效，use-after-move 编译期拦截）。
2. 离开作用域自动释放整块内存（确定性，规范 11.3）。
3. push 是原地操作（对可变所有者）：不移动、不置空。

### 22.4 与定长数组的关系
- `i64[3]`：纯值类型、编译期长度、栈存储、拷贝语义、参数为只读视图。
- `[]i64`：堆类型、运行时长度、可增长、移动语义、参数移动所有权。
- 二者类型互不相容；越界检查都走 `运行时错误：数组越界`。

### 22.5 限制
1. `&` 借用不支持动态数组；需要共享读取时先传副本或未来引入 `&[]T`。
2. 字面量只能出现在声明/赋值 RHS；返回值与传参只接受数组变量或函数调用。
3. 元素不能是 str/结构体/数组（str 涉及所有权、结构体涉及深拷贝协议，均待专项设计）。
4. 不可整体打印、不可比较、不可用于 sel、不可作为结构体字段。

## 23. str 字节访问与子串（v4.2）

1. **`s[i]` 字节读**：返回下标 i 处的**字节**（i64，0–255，UTF-8 按字节诚实处理，不做码点拆分）；越界打印 `运行时错误：字符串下标越界` 并 exit(1)。
2. **`sub(s, start, n)`**：返回从 start 起 n 个字节的新堆串（**新所有者**，归接收变量所有）；越界打印 `运行时错误：子串越界`。
3. **str 不可按下标赋值**（str 不可变；用拼接构造新串）。
4. **借用可转借**：`&str` 形参可以原样传给下一个 `&str` 形参（视图无所有权，无需再次 `&`）。

## 24. 多返回值：元组（v4.5）

按狗粮（统计器需一次返回 count/sum，避免两遍扫描）拍板：**元组 = 多返回值**。

### 24.1 定位：仅存在于函数返回边界

元组**不是一等公民**，不能出现在表达式任意位置（不能作为变量、参数、结构体字段、数组元素、打印对象、sel 分支）。它唯一的合法用途是：

1. **返回**：函数以 `r/e1, e2, ...` 一次返回多个值；
2. **解构**：以 `//a, b = f(...)`（或只读 `/a, b = f(...)`）将返回值按位置解构到多个变量；
3. **@example 期望值（v4.6 唯一例外）**：元组返回的函数，其 `@example: f(...) -> (e1, e2, ...)` 期望值可写元组字面量 `(e1, e2, ...)`，按**逐元素结构比较**校验（数值/bool 用 `==`，str 用 `__t_seq`）。该字面量仅存在于期望值位，不进入一般表达式世界，也不引入元素访问子表达式。

> 设计意图：元组是"返回边界上的打包/拆包语法糖"，解构完成即消失，不进入一般表达式世界。@post 契约不支持元组（元组不可比较、不可访问单个元素）；@example 因需对自测返回整体做值级核对，特此开放元组字面量结构比较（见 24.6）。

### 24.2 类型表示：走类型表

- 元组类型 `Ty::Tuple(id)` 由 **类型表**（线程局部 `tuples`）承载，与结构体/数组表同机制。
- 元素类型签名相同的元组复用同一 `id`（去重），因此 `:(i64, i64)` 的返回类型与 `r/a, b` 的构造类型必然一致。
- 元素支持：`i64` / `i32` / `f64` / `bool` / `str`（str 元素为所有权接管，见 24.4）。

### 24.3 物理布局：malloc 小块，每元素 8 字节槽

- 元组在运行时是一块 **`malloc(N*8)`** 的内存（`void*`），N 为元素个数。
- 元素按下标存入 8 字节槽位：
  - `f64` 元素用 `(double*)` 视图存储；
  - 其余元素（含 `str` 指针）用 `(long long*)` 视图存储，str 元素以 `long long` **重新解释**为指针整数。
- 返回时在函数出口返回该块指针；解构时按类型（`const char*` / `double` / `long long`）把各槽读回对应变量，**随即 `__t_free` 释放该块**。
- 块仅承载值/指针，释放块本身不会释放 str 元素所指向的字符串——字符串随解构出的局部变量，在其作用域出口由天权确定性释放。

### 24.4 天权：按元素接管

- 解构产生的每个变量独立继承其元素类型与可变性（`//` 可变 / `/` 只读）。
- **str 元素**：解构时把槽中的指针**移交**给目标变量（移动语义）；源块释放后该字符串由目标变量独占所有权，作用域出口释放。
- **标量元素**：直接按位复制。
- **移动位**：元组构造/返回中若某元素是 str 变量，则该变量在移动位被置空（use-after-move 编译期拦截），与单值返回语义一致。

### 24.5 语法

```tian
# 函数以 (T1, T2) 标注返回值，r/ 后逗号分隔一次返回
f/range_stats(n:i64):(i64, i64){
    //count=0
    //sum=0
    //i=1
    w/i<=n{
        count=count+1
        sum=sum+i
        i=i+1
    }
    r/count, sum          # 构造元组并返回
}
# 多声明解构：元素按类型接管，块随即释放
//c, s=range_stats(100)
`c
`s

# 含 str 元素的元组：所有权按元素接管
f/pair(n:i64):(i64, str){
    r/n, "hello"
}
//num, label=pair(5)
`num
`label
```

### 24.6 限制

1. 元组不可直接打印（` 元组` 编译期拦截，需先解构）。
2. 元组不可作为结构体字段、数组元素、`sel` 分支与实参（编译期拦截）。
3. `@post` 不支持元组返回值（编译期拦截，规范 24.1 设计意图）。
4. 函数若声明 `(T1, T2)` 返回类型，其 `r/` 必须给出对应数量的元素（检查器核对个数与类型）。
5. `@example` 元组比对（v4.6）：
   - 期望值必须是**元组字面量** `(e1, e2, ...)`，元素个数须与返回类型一致，多/少均编译期报错。
   - 逐元素结构比较：元素类型为 i64/i32/bool 用 `==`，f64 用浮点 `==`，str 用值语义 `__t_seq`。
   - `@example` 契约行必须位于函数体首部（规范 12 节）；元组函数内的变量声明须放在契约之后。

## 25. 关联数组 map[K]V（v4.7）

**哈希表（分离链接）**：以键 → 值映射存储任意键集合，自动扩容。是除动态数组 `[]T` 之外第二种容器。

### 25.1 类型声明与约束

```tian
map[str]i64        # str 键 → i64 值
map[i64]str        # i64 键 → str 值
map[str]f64
map[i64]bool
```

- 键类型 `K` 仅限 `i64` 或 `str`；值类型 `V` 仅限 `i32 / i64 / f64 / bool / str`（标量 + str）。
- 其余键/值类型（含 `[]T`、map、结构体、元组）编译期拦截（`map 键类型须为 i64 或 str` / `map 值类型须为标量或 str`）。
- `Ty::Map(id)` 走**类型表**（线程局部 `maps`）去重：`(K, V)` 签名相同的 map 复用同一 `id`。

### 25.2 创建与字面量

```tian
//m=map[str]i64{}                 # 空 map（可写，后续 m["a"]=1 插入）
m=map[str]i64{"a":1, "b":2}      # 带初值的联合数组字面量
m["a"]=5                         # 已有键则更新值
```

- 空 `map[K]V{}` 或带 `k: v` 条目均可作为字面量。
- 声明用 `/`（只读）或 `//`（可变）前缀；可变 map 后续才能写元素。

### 25.3 索引读写 m[k]

- **读** `m[k]`：返回 `V` 类型的值；键类型与 map 键类型不符编译期拦截。
- **写** `m[k] = v`：`__t_mset_{wire}`，键接管所有权（str 键一律 `__t_dup` 出 map 自有副本，避免形参键双重释放）；`V=str` 时值移动后置空源（字面量 dup）。
- mset 可能触发 bucket 扩容（`realloc` 换头），编译器须把返回的新句柄**写回基变量**（与 `push` 对 `[]T` 的重绑一致）；`K` 元素类型与 `V` 元素类型每个组合一个类型化访问器（`__t_mset_ii`/`__t_mset_ss`/…），槽位运行期类型因此是类型安全的。

### 25.4 内建操作

| 内建 | 语义 | 备注 |
|---|---|---|
| `len(m)` | 键-值条目数 | 表达式 |
| `has(m, k)` | 键是否存在，返回 `bool` | 表达式 |
| `del(m, k)` | 删除键（不存在则空操作） | 语句；str 键/值一并释放 |
| `keys(m)` | 返回**新拥有**的 `[]K` 键快照 | 表达式；遍历 map 的标准方式（见下） |
| `values(m)` | 返回**新拥有**的 `[]V` 值快照 | 表达式；遍历 map 值的标准方式（见下） |

- `keys(m)` 把 map 全部键快照进一个新动态数组 `[]K`（`K=i64` 得 `[]i64`、`K=str` 得 `[]str`），调用方独占其所有权——这是遍历 map 的推荐入口：
  `//ks=keys(m)` 后经 `len(ks)`/`ks[i]` + `m[ks[i]]` 逐键读回键值。
- 实参可为 `map[K]V` 或 `&map[K]V`（只读借用不移动所有权）；map 或 `&map` 均可。
- str 键快照时逐键 `__t_dup`（独立副本，键内存不与 map 共享，释放互不影响）；
  返回数组销毁时深释放这些键，原 map 钥匙照常可用。
- 双后端以共享运行时 `__t_mkeys_i`/`__t_mkeys_s` 落地（bucket 顺序遍历，键序为哈希桶序）。

- `values(m)` 对称地把全部**值**快照进新动态数组 `[]V`（`V=str`→`[]str`、`V=f64`→`[]f64`、`V\in{i32,i64,bool}`→`[]i`（8 字节槽）），调用方独占所有权，遍历/取和不再依赖键。
- str 值快照时逐值 `__t_dup`（独立副本，与 map 释放互不影响）；`f64` 以位模式拷贝。
- 双后端以共享运行时 `__t_mvalues_i`/`__t_mvalues_f`/`__t_mvalues_s` 落地（bucket 顺序，值序为哈希桶序）。

### 25.5 天权：移动语义

- map 是有所有权容器：作为**形参**移动进入被调函数（深释放由被调方承担），**返回值**把所有权交还调用方。
- 改型函数惯例（与 `[]T` 一致）：**接管 → 修改 → `r/m` 归还**。
- map 形参可修改元素（同 darr 形参，规范 22.2）：`record(m, cat){ m[cat]=... ; r/m }`，调用方 `counts=record(counts, ...)` 重新接管。
- 删除/程序退出时深释放：str 键与 str 值随节点一并 `free`，map 头随桶数组释放。

### 25.6 只读借用 &map[K]V

```tian
f/total(m:&map[str]i64):i64{ # 只读视图，不移动所有权
    //s=0
    s=s+m["a"] + m["b"]
    r/s
}
` total(&m)   # 实参 &m 或 m 均可（& 仅是语法糖，同 &[]T，规范 22.8）
` len(m)      # 借用后源变量照常可用
```

- 与 `&[]T` 同规则（规范 22.7/22.8）：只读、可读 `m[k]`/`len`/`has`，**不可写元素**（`变量 'x' 是借用 &map[..]（只读视图），不能写元素` 编译期拦截）、不可 `del`、不可逃逸函数（`r/` 借用的 map 编译期拦截）。
- 实参 `&m` 或裸 `m` 均可；调用后源 map 照常可用。

### 25.7 限制与已知边界

1. map 不可直接打印（编译期拦截；需经 `m[k]` 取值或遍历读取）。
2. map 不可作为结构体字段、数组元素、`sel` 分支（编译期拦截）。
3. map 值类型不含 `[]T`/map/结构体/元组（规范 25.1）。
4. 键/值相等比较均按运行期值语义（i64 数值、str `strcmp`）。

# 2026-09-07 天语言 v4.5 元组多返回值（会话续）

- 在 ZCODE 进度（v4.5 = 多返回值元组）基础上补完剩余代码：type_check 的 check_expr TupExpr 臂、gen_native 的 set_tuples 注入 / MultiDecl / Return 元组分支 / emit_expr TupExpr / emit_move_nulls_native TupExpr / emit_ty_of TupExpr、gen_c 三处 Ty::Tuple 完备臂、fmt 的 TupExpr + MultiDecl 输出。
- **三个关键修复（都是 gen_c 代码生成期发现）**：
  1. 内联 C 运行时缺 `__t_malloc` → 补 `static void* __t_malloc(long long size)`（gen_c.rs 运行时串内）。
  2. **cast 格式串双括号陷阱**：`(long long*)` 这类自带括号的 cast 字符串再套 `(({})…)` 格式会产出 `(((long long*))…)` 非法 C。修法：格式串里只用裸类型名 `pty`/`vty`（"long long"/"double"/"const char*"），由格式串自己加括号：`"(({}*)t_ret)[{}] = ({})({});"`。
  3. **槽位所有者约定**：owned（str/struct）局部槽由 prologue（main 顶层 top_strs / 函数 str_names，经 collect_str_decls 收集 MultiDecl owned 元素名）统一预声明 NULL；MultiDecl 只补声明标量元素，否则 C 重定义。str 元素写入槽用 `(long long)` 重解释指针，读回用 `(const char*)` 转回。
- 原生后端实现：元组 = `__t_malloc(N*8)` 块 + store_field/load_field 每 8 字节槽（复用结构体槽位机制）；MultiDecl owned 名用 prologue 预置槽、标量临时建 Variable；块读毕即 `ctx.rt.free`。
- **验收**：tuple_demo.t（(count,sum) 累加 + str 元素 + 透传解构）双后端输出一致 `100/5050/5/hello/3/7`；`tc fmt` 幂等且格式化后可重编译；cargo test 45 全绿（新增 test_gen_tuple_v45、test_gen_tuple_str_elem_v45 两个回归测试）。
- **fmt 陷阱**：TupExpr 是 r/ 专属（元组仅存在于返回边界），fmt 必须输出 `r/count, sum`（无括号逗号分隔），带括号 `r/(count, sum)` 解析器报"期望 ')'，实际 ','"；ty_str 需为 Ty::Tuple 还原 `(i64, i64)`（否则输出 `:tuple` 不可重编译）。
